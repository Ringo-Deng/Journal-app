# 拾光 · 私人手帐

本机使用的电子手帐第一版。每月一本、每天一页，相邻两页共享风格与跨页装饰。跳过未记录的日期；补写默认追加到当前月份末尾，保持已经完成的跨页组合。

## 介绍网页

启动拾光后，在当前网页地址末尾加 `/intro/index.html`，即可打开独立介绍页。页面以真实 App 截图展示笔记编辑、素材工作台、照片库与欣赏页面，支持切换场景、放大和查看原图，并列出首次安装步骤；当前仓库为私有仓库，页面说明试用文件由作者提供，项目链接需要访问权限。仅在当前本机地址检测到拾光服务时显示“进入当前运行的手帐”；该链接不安装或启动程序。介绍页不读取或修改私人手帐，手机也可以浏览。源文件在 `public/intro/`，生产构建从包版本自动写入左下角的唯一版本标签。

## 完整资料备份与恢复（v0.1.188）

点击左侧「备份」打开「备份与恢复」，选择「备份全部资料」。程序先保存当前手帐，再打包并校验；完成后点击「下载完整备份」，保存 `.shiguang-backup` 文件。备份包含笔记与排版、照片库原片及缩略图、内置和自定义素材、分类标签、素材处理与来源记录、自定义字体、历史备份和照片回收站。AI 设置及密钥、浏览器临时状态、应用代码和运行缓存不入包。

在另一台支持拾光的电脑上，安装本版或兼容新版，点击「选择完整备份」。程序先检查文件内容和图片引用，展示资料数量，再由你点击「确认恢复为新增资料」。笔记本和素材以新身份加入，保留已有内容；相同照片原片和字体按内容复用，同一份完整备份重复导入会跳过。内置 SVG 素材的恢复副本转为 PNG，使原版素材变化后仍可显示。

恢复准备阶段失败不会修改现有资料；提交中断时，下次启动先继续完成恢复。恢复后的其他旧窗口仍须刷新，过期保存会被原有版本冲突保护拦截。导入的历史备份单独保留，日常自动快照仍保留最近 30 份。资料缺失、文件损坏、路径无效或正在进行其他资料处理时，完整备份操作会停止并提示。

大文件分段读写，单文件上限 128 MiB，清单上限 64 MiB，最多 100,000 个文件、总计 100 GiB。打包和恢复需要额外临时磁盘空间；下载及预览链接有效期为 30 分钟。完整备份没有加密，请保存在你信任的位置。旧版 `.json` 手帐备份仍可通过窗口中的「旧版手帐备份」导入、导出；它不包含完整素材库和照片库。

## 打开

- Mac：先安装 Node.js 22.21.0 或更高版本，再双击本目录的 **启动拾光手帐.command**。
- Windows 10/11：先安装 Node.js 22.21.0 或更高版本，再双击 **启动拾光手帐-Windows.cmd**。第一次启动会按项目依赖清单安装运行环境，完成后自动打开浏览器。

使用期间请保留启动窗口。应用只监听本机地址，手帐资料仍保存在当前应用目录的 `data` 中；AI 设置在 Windows 保存在 `%APPDATA%\ShiguangJournal`，在 Mac 保存在 `~/Library/Application Support/ShiguangJournal`。

点击封面打开手帐，然后选择“记录今天”。添加文字与照片后，可先用“本地排版”体验：它保留原文，不调用 AI。填写左侧齿轮里的 API 地址、模型名称和密钥后，“一键做成手帐”会调用你的在线模型。

## 已有功能

- 四款可修改标题和装饰的月度封面、立体开合效果、左右跨页、页角翻页与方向键翻页。
- 68 张已下载的复古图片：花卉与植物 43 张、蝴蝶 8 张、邮票 8 张、旧纸手稿 6 张、鸟类 3 张。素材面板支持搜索、分类和来源查看。
- AI 忠实整理日志，选择主题、素材和留白／拼贴／信件版式。未配置 AI 时明确使用本地排版，不伪装成 AI 生成。
- 第一天铺好跨页风格，第二天沿用；重新设计整个跨页时，保留手动修改过的元素和删除记录。
- 文字、照片、素材独立拖动、缩放、旋转、调整前后顺序与删除；照片支持裁切位置、拍立得、撕纸、邮票边框及恢复原图。
- 本机图片处理不上传照片：Apple Silicon Mac 继续使用系统 Vision；Windows 可处理透明图、白底／单色纸底素材和背景较单一的主体。复杂照片在 Windows 识别失败时保留原图并提示使用裁切。
- 自动保存、当前会话撤销、日期索引、包含原图的导出备份、导入不冲突月份。
- 浏览器支持时可语音转文字；不支持时可使用系统听写。

## 数据位置

- `data/journal.json`：手帐正文、月份和排版。
- `data/journal.previous.json`：上一次成功保存的数据。
- `data/journal-history/`：每日首份及删除笔记本、跨页或扉页前的历史快照，保留最近 30 份健康快照；损坏文件保留并提示。
- `data/uploads/`：原始照片和本地抠图结果。
- `data/settings.json`：本机 API 设置，密钥不返回浏览器、也不进入导出备份。文件权限为仅当前用户可读写，未做额外加密。
- `public/materials/manifest.json`：素材标签、作者、来源页面、下载链接及来源声明的授权信息。

手帐不依赖浏览器缓存。建议定期使用左侧的“导出备份”。导入备份会新增笔记本副本，保留现有内容。

在笔记库点击“历史备份”，选择时间并查看笔记本概要，再点“恢复为副本”，可将当时的笔记本重新加入当前手帐。已有手帐在每天首次保存前自动留存，删除笔记本、跨页或扉页前也会另存一份；普通连续编辑不会每次生成快照。快照只保存原图路径，图片仍引用 `data/uploads/` 等本机原文件；迁移电脑时应使用包含原图的导出备份。历史快照写入失败时，正常保存仍可完成，但页面会单独提示备份失败。

当前主文件 `data/journal.json` 已损坏而导致服务无法启动时，本轮尚未提供启动恢复入口；应用内历史预览与恢复需要本地服务正常运行。

## 当前边界

这是可以使用和继续迭代的第一版。翻页为 CSS 立体动画，尚未实现跟随手势的连续纸张物理卷曲；封面有开启动画，合上时返回封面。长日志保留全文，超出纸面区域的正文可在文字区域内滚动，也可在编辑面板修改。

AI 接口按 OpenAI 兼容的 Chat Completions 格式接入。已通过本地模拟服务验证请求、解析、错误反馈和照片发送开关；尚未使用真实供应商密钥测试生成质量。默认只发送文字，照片只有在设置中开启“让 AI 理解照片”后才发送给所选供应商。语音识别可能由浏览器的在线服务完成。

WebMCP 在支持的浏览器中仅提供“准备一篇手帐”操作，尚未在支持该标准的浏览器中验证。不支持不影响正常使用。

## 素材工作台

点击左侧“素材库”，再点击“导入与拆分”。导入 JPG、PNG、WebP（单张 10 MB 以内，可多选）后，自动拆出独立透明 PNG。选择结果、修改名称和分类标签，点击“入库”。新素材会出现在素材库中，也进入 AI 排版候选库。

自动模式优先分离透明或浅色纸底；复杂背景在 Mac 使用 Vision 主体识别，Windows 保留适合本机稳定处理的自动、纸底和密集素材模式。纸底分离使用背景颜色与连通区域分析，不调用在线模型。素材之间留有间隔时更容易拆开；粘连或漏检可使用原图框选、调整去底强度或切换模式。处理图片最长边限制为 2400 像素，原始上传图仍保留；每次最多拆出 100 个结果。

原图与独立 PNG 保存在 `data/uploads/`，入库清单保存在 `data/materials.json`，处理历史保存在 `data/material-jobs.json`。保留整个 `data` 文件夹可完整备份工作台；原有手帐导出只包含手帐记录及其引用图片，尚不包含工作台历史和整个素材库。

## 内页与日期

翻开手帐后，点击纸张上方的“内页样式”，可选空白、方格、点阵，以及预设或自定义颜色。默认是白色空白页。可以应用到整本（包括之后的新页），或只设置当前跨页；AI 重新排版不会覆盖这些选择。

固定日期页眉已取消。需要日期时，点击“添加日期”，选择日期、格式与左右页位置；添加后作为独立文字元素，可拖动、编辑或删除。

内置素材已改用透明 PNG；植物图谱额外清除了扫描页边框和纸底。原 JPG 保留在本机供回溯，清单中记录在 originalSrc；纸张本身作为素材时保留其纸面设计。

## 2026-09-05：纸面编辑与完整跨页设计

双击纸上的文字直接输入；点击元素后在纸面浮动工具栏调整大小、角度、文字颜色和文本框样式，照片可直接替换。拖动位置、缩放和旋转仍可直接在纸上完成，“更多”打开完整属性侧栏。编辑不再自动锁定；可以主动锁定元素。

记录与页数独立，同一天可有多条记录、多个跨页。工作台翻过最后一页会新建空白跨页，欣赏模式只翻阅已有页。重新设计默认处理整个左右跨页，保留最新原文和照片；勾选“保留已锁定元素的位置和样式”才会保留锁定布局。

AI 接口返回逐元素的坐标、字号、配色、文本框和结构化涂鸦路径，素材候选包括标签信息。重设计发送当前纸面内容，校验原文及照片引用的完整性；无效设计报错，保留原页。没有 AI 连接时不再用本地模板冒充重新设计。

验证：17 项自动化测试、类型检查和代码检查通过；真实已配置 AI 接口使用虚构咖啡日志验证左右页指定、绿色边框、咖啡杯与雨滴涂鸦及无植物要求。浏览器使用独立测试数据确认绘制、纸面编辑保存与最后一页后新增跨页；没有将测试记录写入正式手帐。

## 2026-09-05：纸面放大与 DeepSeek 响应修复

纸面默认放大，工具栏可选择适合窗口、115%、130%、150%；超出窗口时可滚动查看。减少周围留白，放大时工具栏和翻页按钮仍在窗口范围内。

复现发现旧接口在读取响应正文时触发 90 秒中断，却被统一报成“无法排版”。DeepSeek 官方接口现使用严格 JSON 输出并显式关闭长思考模式，已有文字通过 ID 引用，减少重复输出。分别处理空响应、截断、格式错误、服务拒绝、超时及布局不完整；可修复的格式或布局错误自动重试一次。诊断仅保存耗时、结束原因、用量、错误分类，不保存日志正文、图片或密钥。

同一份虚构复杂跨页测试修复后约26秒成功（含一次自动修复）。当前配置的视觉模型另通过纯蓝色测试图验证，HTTP 200并回答蓝色。21项自动化测试通过，涵盖重试、诊断和不同响应格式。

## 2026-09-05：按指令润色分段与逐段设计

封面取消静态及悬停倾斜。AI 先识别指令并整理文字，再为整理后的独立段落设计跨页：只要求排版时保留文字；明确要求润色、改写或分段时使用新段落，原始日志和撤销记录保留。每段可独立编辑，同一条日志拆段后会汇总保存其最新文字。

指定段落数量、逐段边框和贴纸时会校验完成情况与文字区域重叠。贴纸按具体事物关键词匹配素材；没有匹配素材时用相关手绘贴纸，常见咖啡、绿植、明信片等主题使用清晰线稿。未通过检查的结果重试一次，不覆盖原页。

以“帮我把日志润色成三个段落，然后给每个段落设计框框，并且配上合适的贴纸”调用当前AI，虚构日志实际生成三个独立段落和三张主题贴纸；约15秒返回。浏览器检查了摆正封面、分段文本框、贴纸渲染；25项自动化测试通过。

## 2026-09-05：排除未填写提示框

“写在这里…”这种尚未填写的自由文字框，以及标题、日期、空文字，不再被要求纳入日志润色分段；这些对象保留在页面。真实正文与已填写的自由文字仍受完整性检查。内容编辑请求显式提供必须覆盖的正文编号，若漏引，重试提示会指出具体编号。新增占位提示与真实自由文字的回归检查，27项测试通过。

后续排版同样允许省略空提示框，程序原样补回而不要求AI改写；真实文字仍不可遗漏。逐段加框的明确要求由程序补齐缺省边框。使用当前真实跨页（含两条正文、标题及未填写提示框）调用同一条三段润色指令，约17秒成功返回三段、三个框、三张关联贴纸；测试仅检查返回结果，未写入正式手帐。28项自动化测试通过。


## 左侧素材库与 AI 归类

左侧“素材库”集中展示内置与导入素材，支持名称／主题标签搜索，以及风格、用途、自定义分类、原有分类筛选。可创建自定义类别，批量添加或移除分类；多选后选择左页或右页插入当前跨页，每次最多24件，整批插入可以撤销。

AI 可处理全部素材、筛选结果或已选素材，按“风格＋用途”“自定义分类”或三个维度一起归类，并遵循补充规则。分类按6件一批后台执行，有进度、停止与建议预览；逐件勾选确认后才保存。关闭素材库不打断后台任务，重新打开可恢复结果。服务重启后保留已完成建议，未完成部分需重新发起。

开启“看图识别”会把384像素以内的素材缩略图发送给当前配置的AI服务；未开启时仅按名称与标签归类。分类元数据独立保存在 `data/material-catalog.json`，任务与建议保存在 `data/material-classification-jobs.json`，不改原图或纸面已有内容。完整备份素材库仍需保留整个 `data` 文件夹。

验证：33项自动化测试、类型检查、代码检查和生产构建通过；独立测试数据中使用实际AI看图归类玫瑰与邮票，浏览器验证建议保存、自定义类别、搜索、左右页插入、整批撤销与重新进入后的分类恢复；自定义规则“只有邮票归入旅行收藏，植物不要归入”也通过真实AI验证。测试未修改正式手帐或正式素材分类。

## 密集贴纸与手动补拆

自动识别粘连时，可选“密集贴纸（细分）”：使用原像素间隙、去除细小连接并过滤小碎屑；图片角落被贴纸覆盖时从亮色中性采样估计纸底。真正接触的贴纸仍可能合并，不保证自动拆净。

“框选单个素材”现在提供“框选整件去底”和“保留原底裁出一件”，均固定输出一件，避免文字再次拆散。浅色字、有色底和去底损伤时优先保留原底。结果保存在新的导入记录中，原图与历史结果保留，确认后入库。

## 简单自然的手绘点缀

新生成的跨页采用手绘点缀模式：文字模型只选择motif、颜色、位置和关联段落，不直接编写复杂绘图坐标。提供下划线、波浪线、弯箭头、手绘圈、爱心、星光、咖啡、信封和雨滴9种不对称细笔曲线。程序约束各自尺寸和比例，每跨页最多6处，透明无填色；线宽固定，缩放不变成厚边。复杂物体应选择相关素材，旧手帐已有路径和插画继续兼容显示。

42项测试、类型检查、代码检查、生产构建通过，包含真实HTTP链路的模拟AI输出检查、数量／尺寸上限和正文完整性保护。独立测试手帐中已目视检查全部9种点缀。此次未验证真实供应商的新排版质量。过程中制作的两张细致插画仅保存在本地预览目录，未作为默认风格或自动加入用户素材库。

## 贴纸按主题、风格和色系搭配

取消逐段贴纸必须命中stickerKeywords的限制，关键词仅供参考。逐段配贴纸仍检查关联关系、邻近位置和素材是否存在，正文及照片完整性检查保留。候选池保留不同分类素材，不因主题未命中而清空；生成时本机提取图片主色，透明及近白背景不计入，结合设计方案色板排序，同时将主色值提供给AI。主色计算失败不阻断排版。

45项测试通过，包括无关键词也有多样候选、配色可优先于字面主题、花卉可用于咖啡段落，以及缺失贴纸仍被发现。主色提取使用macOS程序，可用 `xcrun swiftc local/material-palette.swift -o local/material-palette` 重新编译。

## macOS 桌面测试版

首版支持 macOS 26 或更新系统的 Apple 芯片 Mac（现有原生图片程序的最低系统版本为 26.0），使用 Electron 独立窗口，内置运行环境；使用者无需安装 Node.js。开发仍共用本仓库界面和本地服务。

- 开发预览：`npm run desktop:dev`（先构建页面）。
- 打包：在 Apple 芯片 Mac 执行 `npm run desktop:mac`。产物在 `build/desktop/`，包含 `.app` 和带版本号的 ZIP；解压后将「拾光手帐.app」放入「应用程序」。
- 本轮产物只有本机 ad-hoc 签名，**没有 Developer ID 签名及 Apple 公证**，用于受控测试；不能保证其他 Mac 的 Gatekeeper 放行，正式对外分发前需签名、公证和另一台 Mac 验收。
- 桌面数据：`~/Library/Application Support/ShiguangJournalDesktop/data`；AI 配置在同级 `config`。替换 App 不替换这个目录。应用菜单可打开资料文件夹。
- 首次运行为空白资料，不自动读取源码版的 `data/` 或 AI 设置。旧版先导出「完整资料备份」，再在 App 内追加恢复；保留原资料及备份，验证后再决定是否继续使用旧版。AI 密钥需单独设置，不包含在分享包内。
- 退出会先等待手帐保存；保存冲突、失败或后台仍在处理时保留窗口。只允许一份桌面实例；源码版与桌面版使用不同数据目录。
- 手动更新：正常退出旧 App，再替换应用程序中的 App。暂不提供自动更新，暂未支持 Intel Mac 或 Windows 桌面安装包。

打包按受控源码及构建文件白名单收集，只带后台所需的 `sharp` 依赖及其原生模块，不收集工作区私有数据、配置或 Git 历史。测试必须使用 `SHIGUANG_DESKTOP_TEST_DIR` 指定隔离目录，禁止使用正式资料做自动化保存测试。
